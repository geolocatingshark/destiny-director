# Preview render fixtures — the shared golden corpus

These files freeze what a Discord message preview renders to. They were written to make
moving the renderer from Python to JavaScript (`docs/architecture.md`, "Rendering a
message on the web")
*provably* behaviour-preserving rather than hopefully so — every expectation here was
generated by the old Python renderer, and the JavaScript one had to reproduce it byte
for byte before the Python was deleted.

That move is done, so the two sides now own different halves:

- `dd/anchor/tests/test_preview_fixtures.py` asserts the **data** — the diff
  annotations, the sanitize downgrade, a hybrid post's node tree — and audits every
  recorded expectation against the tag/attribute/URL whitelist.
- `dd/anchor/web_static/tests/preview_fixtures.test.js` asserts the **drawing**: the
  shared renderer still turns each case into exactly the frozen string.

## Case shape

```json
{
  "name": "container_with_accent",
  "render": "snapshot" | "authored" | "diff" | "post_spec",
  "kind": "cv2" | "classic",
  "payload": { … },
  "old_kind": "cv2",
  "old_payload": { … },
  "spec": { "body": "…", "image_url": "…", "buttons": [["label", "url"]] },
  "emoji": { "kyber": "https://cdn.discordapp.com/emojis/1.png" },
  "expected_html": "…"
}
```

`render` picks the entry point:

| value | what it draws | the data field it draws from |
|---|---|---|
| `markdown` | one text leaf, via `cv2_model.renderMd` | `content` |
| `snapshot` | a captured message, via `snapshotSpec` | `payload` + `kind` |
| `authored` | the builder's confirmation | `sanitized` (from `cv2_nodes.sanitize_for_preview`) |
| `post_spec` | a hybrid-post form preview | `nodes` (from `hybrid_post_core.post_spec_nodes`) |
| `diff` | the mirror log's version diff | `annotated` (from `cv2_render.diff_payload`) |

The data fields are generated, never hand-written — Python produces them, JavaScript
renders from them. That split is the production one: aligning two trees needs `difflib`
and stays server-side, drawing the result belongs to the one renderer.

`emoji` maps a name to a URL string. Python wraps each in a duck-typed stand-in (the
substituter only reads `.url`); JS accepts the bare-string map directly
(`cv2_model.js` `emojiEntry`).

## The frozen clock

`<t:…:R>` renders a *relative* string off the render-time clock, so the corpus pins
`now` to 2026-07-30T17:00:00Z (`NOW_MS` in the JS test). Every other format letter is
absolute and needs no freezing. The renderer threads `now` as a parameter
(`renderMd(content, emoji, now)`), so nothing has to be patched — a clock you can pass
in is why this is a one-line concern rather than a monkeypatch.

## Regenerating

Two steps, in this order — the JS render reads the data fields Python writes:

```sh
UPDATE_PREVIEW_FIXTURES=1 uv run --env-file .env python -m pytest \
    dd/anchor/tests/test_preview_fixtures.py
UPDATE_PREVIEW_FIXTURES=1 node --test \
    dd/anchor/web_static/tests/preview_fixtures.test.js
```

Running both on an unchanged tree reproduces the corpus byte for byte.

**Regenerate only when you mean to change rendered output**, and read the diff — that
diff is the whole point of the corpus. During the port, a case whose behaviour is
deliberately being corrected (the drift items in the plan) gets its expectation updated
in the same commit that corrects it, so the change is visible in review.
